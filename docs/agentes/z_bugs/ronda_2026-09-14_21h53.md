## Detalle por corrección

### 1. CORS allowlist hardcodeada en el binario (N1 del Director — severidad MEDIA-BAJA)
- **Descripción:** `corsMiddleware` contenía un mapa literal con tres orígenes de desarrollo. Consecuencias: (a) cualquier despliegue real emitía `Access-Control-Allow-Origin` para orígenes `localhost` que no le pertenecen (un `localhost:9090` en la máquina de un operador podía llamar al API con credenciales del navegador... sin cookies no es una fuga directa, pero es superficie y ruido); (b) la política no era ajustable sin recompilar; (c) un auditor externo no podía verificar la política sin leer Go. Hallazgo #5 del backlog desde la ronda 6.
- **Solución** (`internal/config/config.go`, `internal/handlers/router.go`, `cmd/server/main.go`, `config.example.yaml`):
  - `APIConfig.AllowedOrigins []string` (`api.allowed_origins`), vacío por defecto.
  - `parseAllowedOrigins()` normaliza (trim, sin barra final), descarta vacíos y **pánico si un entry contiene `*`** — wildcard CORS en un C2 es un regalo a cualquier página que el operador visite; fail-fast al arrancar, coherente con el patrón de `trusted_proxies`.
  - El middleware solo emite `Access-Control-Allow-Origin` para orígenes del allowlist exacto, y añade `Vary: Origin` (corrección de cacheado: un proxy que cachee la respuesta de health/status no debe servirle a B la respuesta con el grant de A).
  - **Cero orígenes por defecto:** la consola bundled se sirve same-origin y no necesita CORS; los orígenes de desarrollo quedan documentados (comentados) en `config.example.yaml` para quien los necesite.
- **Tests** (`internal/handlers/router_cors_test.go` — primer fichero de tests del paquete):
  - `TestParseAllowedOrigins`: allowlist vacía con config vacía; normalización exacta (trailing slash, espacios); **wildcards en pánico** (`*` y `https://*.example.com`).
  - `TestCORSAllowlistBehavior`: origen configurado → ACAO + `Vary: Origin`; origen no configurado → nada; **allowlist vacía nunca emite ACAO ni para los viejos orígenes de dev** (regresión guard); preflight OPTIONS sigue respondiendo 200 pero sin grant para orígenes no configurados.
- **Verificación (en vivo):** con `allowed_origins: [http://localhost:5173]` en el config del smoke — `Origin: http://localhost:5173` → `Access-Control-Allow-Origin: http://localhost:5173` + `Vary: Origin`; `Origin: https://evil.example` → cero cabeceras CORS; wildcard en config → el servidor no arranca (pánico con mensaje claro).

### 2. Audit logs de autenticación sin normalizar proxy (N2 del Director — severidad BAJA, forense)
- **Descripción:** tres puntos de logging usaban `req.RemoteAddr` crudo: `handleLogin` (`auth_failed`), `authMiddleware` (`auth_failed` por token inválido) y el evento SIEM `operator_login` (`remote`). El rate limiter ya resolvía la IP real con `trusted_proxies`, pero el audit trail no: detrás de un reverse proxy, cada intento fallido quedaba atribuido a la IP del proxy — en un incidente, el operador no podría distinguir 50 intentos de un atacante de 50 errores legítimos detrás del mismo proxy. Hallazgo #6 del backlog desde la ronda 6.
- **Solución** (`internal/c2/ratelimit.go`, `internal/handlers/handlers.go`, `internal/handlers/router.go`):
  - Nuevo `RateLimiter.ResolveClientIP(r)` — wrapper exportado de `clientIP` con el contrato documentado: socket peer salvo peer trusted-proxy, en cuyo caso se recorre XFF derecha-a-izquierda.
  - Los tres puntos de logging migrados a `r.rateLimiter.ResolveClientIP(req)`. El `api_call` del `auditMiddleware` también (perdía el host-port que SplitHostPort ya recortaba — ahora registra exactamente el mismo valor que keyea el bucket).
  - **Una sola fuente de verdad:** auditoría y rate limiting usan la misma resolución, así que nunca pueden discrepar sobre quién es el cliente.
- **Test** (`internal/c2/ratelimit_test.go` — `TestResolveClientIPForAudit`): sin proxies → peer; con proxy trusted + XFF → cliente reenviado.
- **Verificación (en vivo):** smoke con proxy no configurado — el `auth_failed` tras un login fallido registra la IP del cliente de prueba (no la del proxy inexistente), y un agente real conecta sin regresión tras tocar `ratelimit.go`.
