### Mejora 1: paleta de comandos (`Ctrl+K` / `Cmd+K`)

- **Motivación:** la consola creció a diez vistas en 18 rondas; navegar es movimiento de ratón puro. Un C2 moderno merece salto por teclado.
- **Frontend (`App.vue`):** overlay + diálogo con input auto-enfocado, lista filtrada por subcadena (case-insensitive) sobre **todas las vistas que el rol actual puede abrir** — el filtro espeja la tabla de rutas (`requiresAdmin` oculta Webhooks/Operators a no-admin; `roles:['admin','auditor']` oculta Audit al resto) — más la acción **Logout**. Navegación con ↑/↓ (wrap-around), `↵` ejecuta, `Esc` cierra, hover sincroniza la fila activa; `@click.self` en el overlay también cancela. Un chip «Jump to… `Ctrl K`» en el topbar hace el atajo descubrible y clicable. El listener global vive en `window` con cleanup en `beforeUnmount`; la paleta no se abre en la pantalla de login. Sin dependencias nuevas; estilos del sistema oscuro compartido.
- **Seguridad por diseño:** la visibilidad por rol es UX — **los guards de ruta y los gates de API siguen siendo la autoridad**; ocultar no es autorizar.
- **Cómo probarla:** spec E2E `round18.spec.js` «command palette opens with Ctrl+K, filters and navigates» — abre con Ctrl+K, verifica foco, filtra «vault» a un único resultado, `Enter` aterriza en la vista Vault, `Esc` cierra tras reabrir.

### Mejora 2: atribución de auditoría por operador + `?user=` (backlog r17 #1)

- **Motivación:** `audit_log.operator_id` existía desde la migración 1 — y **todos** los escritores pasaban 0 (encontrado por `rg "LogAction"`: cero llamadas con id real). «¿Quién hizo qué?» exigía leer texto libre.
- **Backend:** `db.OperatorIDByUsername(username) (int, error)` devuelve `(0, nil)` para desconocidos (contrato espejo del antiguo `OperatorExists`, que queda **eliminado como código muerto** — Pulimiento). El middleware de auth usa ESA consulta (un lookup indexado, dos respuestas: existencia + id) y publica el id como `X-Auth-UID`; el middleware de auditoría lo parsea (estricto: vacío/inválido → 0 = sistema) y lo escribe; el login escribe `auth_success` con `operator.ID` real. Los eventos del core C2 (task/session) siguen en 0 = sistema, que ahora además **se distingue en la API**.
- **Lectura:** `ListAuditEntries(limit, action, user)` hace LEFT JOIN con `operators` y expone `operator` (username resuelto, `""` para sistema). `?user=NAME` — igualdad exacta, ≤ 64 chars, siempre parámetro enlazado; desconocido → `[]` 200 (sin oráculo de existencia); combinable con `?action=` (intersección, no unión). Bajo filtro de usuario las filas de sistema se excluyen — la semántica honesta de «qué hizo ESTA cuenta».
- **Frontend (`Audit.vue`):** columna **Operator** nueva (pill acentuada para filas atribuidas, marcador apagado «system» para el resto) y select **server-side** de operador (opciones construidas desde la página cargada — sin ensanchar el endpoint) que dispara `?user=` con `encodeURIComponent`.
- **Cómo probarla:** `TestAuditOperatorAttribution` (DB: JOIN, sistema "", filtros) y `TestAuditUserFilter` (HTTP: atribución real tras login, semántica completa del filtro); en vivo, smoke checks 3-8.

### Mejora 3: retención del audit log (backlog r17 #2)

- **Motivación:** la traza crecía sin techo (riesgo #5 del registro r17) — cada llamada API añade una fila.
- **Config:** `audit.retention_days` (0 = conservar para siempre, el default histórico; documentado en `config.example.yaml`).
- **Backend:** `db.PruneAuditOlderThan(days) (int64, error)` — `DELETE … WHERE timestamp < datetime('now', ?)` con el modificador enlazado como parámetro; `days <= 0` es no-op documentado. El servidor lanza `auditRetentionLoop` en `Start()` cuando la política existe: una pasada inmediata (un reinicio aplica la política a lo que dejó el proceso anterior) y luego horaria; cada poda suma a `auditPrunedTotal` (atómico) y deja línea de log. Fallos de poda: log y reintento en el próximo tick — never disturb the server.
- **Observabilidad:** `worldc2_audit_entries` (COUNT(*)) y `worldc2_audit_pruned_total` en `/api/metrics`.
- **Verificación en vivo:** dos filas con timestamp de hace 40/35 días insertadas directamente en la BD; reinicio → `[AUDIT] retention: pruned 2 audit rows older than 30 days` y `worldc2_audit_pruned_total 2` en el scrape. `TestAuditRetentionPrune` pina el contrato (3 viejas fuera, 2 frescas dentro, idempotente, no-op con 0/negativos).

### Mejora 4: test de entrega de webhooks

- **Motivación:** configurar un destino SIEM y descubrir que estaba mal escrito cuando un evento real se perdía era la única opción — 18 rondas sin «probar ahora».
- **SIEM (`forwarder.go`):** `TestDelivery(id) (found bool, err error)` — localiza el destino, dispara un evento sintético **síncronamente** (acotado por el propio timeout del destino) y pliega el intento en el MISMO ledger con `recordResult`. El evento `webhook_test` lleva solo `{webhook_id, note}` — cero datos del engagement (sin hostnames, sin usuarios) — y **sortea deliberadamente la suscripción de eventos**: la alcanzabilidad es el punto; el forwarding automático sigue honrándola.
- **Handler:** `POST /api/webhooks/test?id=` (admin, misma puerta que el CRUD) — 400 sin id, 404 desconocido, 405 no-POST; el RESULTADO es el body: 200 `{"delivered":true}` o 200 `{"delivered":false,"error":"…"}` con el error de transporte acotado a 200 chars (un endpoint hostil no puede inflar la respuesta).
- **Frontend (`Webhooks.vue`):** botón de envío por fila (spinner por-id mientras vuela — la prueba espera hasta el timeout del destino), notificación honesta del resultado y refresco del ledger al terminar. Icono `IconSend` nuevo en el set inline (sin librería externa).
- **Cómo probarla:** `TestWebhookTestDelivery` (receptor vivo → delivered:true + hit; puerto muerto → delivered:false + error acotado; ledger actualizado; 400/404/405/403 viewer) y el spec E2E que ejercita el botón contra un puerto muerto y exige el toast de fallo honesto + el badge `failed` en la fila.
