## Decisiones tomadas por ti en esta ronda

1. **Las capturas se hacen contra un agente REAL, no contra datos sembrados a mano.** El repo tiene un agente funcional: conectado por HTTP al servidor de captura, ejecuta 10 comandos reales (`whoami`, `uname -a`, `ss -tlnp`…) y esas salidas son las que se ven en sessions.png y terminal.gif. Un README de una herramienta de seguridad debe enseñar la herramienta funcionando, no maquetas.
2. **El filtro de auditoría es server-side, no otro filtro cliente.** El atributo lleva el actor en una COLUMNA; «qué hizo esta cuenta» debe poder recorrer toda la traza por API (`?user=`), no solo la página cargada. El select de la vista dispara la query real (el spec E2E lo pina interceptando la petición).
3. **El resultado de la entrega de test es el payload, no el status HTTP.** Un destino muerto es el RESULTADO de la prueba (200 + `delivered:false` + error acotado), no un 500 — el endpoint informa la verdad en lugar de disfrazarla.
4. **La retención es configuración opt-in, nunca default.** 0 = conservar para siempre (el comportamiento histórico); la poda solo existe si el operador la pide, y lo que poda queda contado en `worldc2_audit_pruned_total`.
