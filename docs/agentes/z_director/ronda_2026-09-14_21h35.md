## Decisiones tomadas por ti en esta ronda

1. **Recorte de health en lugar de autenticarlo**: el healthcheck de Docker y balanceadores no hablan Bearer; la liveness debe seguir pública. La telemetría es la parte sensible, y esa es la que se movió detrás de auth con un permiso ya existente (`sessions:list`, que todos los roles poseen — no se rompe ningún flujo de operador legítimo).
2. **`/api/status` en lugar de reciclar el nombre health**: la URL pública cambia de semántica (menos campos) y la nueva semántica completa merece nombre propio; documentado en OpenAPI con schema separado (`Health` vs `Status`).
3. **Purge estricto en vez de idempotente**: para operaciones destructivas, el silencio ante ids erróneos es un anti-patrón; el "borrar lo que no existe no es error" se mantiene en la capa DB (storage tonto) y la semántica HTTP la pone el server (404). Contrato fijado con test para que un cambio de driver no lo voltee.
4. **Fleet panel con heurística de "versión dominante"**: marcar como outdated todo lo que no sea la versión más frecuente es simple y correcto en la práctica de laboratorio; una política de versión mínima configurable sería el siguiente escalón (backlog, no ronda).
5. **Baseline re-registrado:** build ✅, vet ✅, gofmt vacío, suite `-race` verde (7 paquetes), `npm run build` OK. Smoke en vivo 4/4.
