## Detalle por cambio

### 1. Poda de la capa muerta `task_queue` (decisión de producto)
- **Qué y por qué:** la cola offline de tareas (`QueuedTask`, `QueueTask`, `GetPendingTasks`, `MarkTaskDelivered`, `CompleteTask`, `ListQueuedTasks`, `DeleteQueuedTask`, `scanQueuedTasks` — ~100 líneas) llevaba sin una sola llamada desde su creación: el flujo real usa la tabla `tasks` vía `InsertTask`. El Director decidió **podar el código** y conservar la **migración 7** en el ledger: quitar la migración rompería la integridad histórica de las BDs existentes (y dejaría una tabla huérfana inofensiva), mientras que implementar la feature sin tests no cumple el criterio de riesgo de este rol.
- **Archivos modificados:** `internal/db/database.go`.
- **Impacto esperado:** ~100 líneas menos de superficie muerta que confundir; `go vet` y suite completa siguen verdes.

### 2. Sincronización de README (honestidad)
- **Qué y por qué:** la fila de multi-transporte del README marcaba el long-poll HTTP como experimental/no alcanzable — tras la reparación de esta ronda eso vuelve a ser falso, y el propio README lo prohíbe. Actualizada la fila (los cinco transportes funcionales), reescrito el bloque de "Known gaps" (ronda 2): describe el transporte reparado con su cadena de fallback explícita, mantiene el aviso de auto-persistencia con `-no-persist`, y lista el backlog abierto real (anti-replay, reaper de túneles, KDF).
- **Archivos modificados:** `README.md`.
- **Impacto esperado:** el README cumple de nuevo su política: cada ✅ es verificable en el código y en los tests.

### 3. Sincronización de QUICK_REFERENCE y DEVELOPER_GUIDE

- **Archivos modificados:** `docs/QUICK_REFERENCE.md`, `docs/DEVELOPER_GUIDE.md`.
